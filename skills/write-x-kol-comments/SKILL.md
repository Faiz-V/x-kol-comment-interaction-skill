# Write X KOL comments

Create useful reply options that add one clear point of view without pretending to be an independent person, inventing facts, or automating engagement.

## Process the source

1. Read the screenshot, link content, or pasted text.
2. Separate explicit source claims from interpretation.
3. Identify the single most discussion-worthy signal: a trend, trade-off, pressure point, mechanism, or unanswered question.
4. Note any claim that is current, uncertain, numerical, causal, or reputation-sensitive.
5. Verify current claims when verification is requested or essential. If verification is unavailable, stay within the supplied source and use conditional wording such as `if true`, `if accurate`, or `assuming the figures are right`.

Do not silently add statistics, quotes, sources, motives, injuries, diagnoses, or causal conclusions.

## Generate five distinct directions

Unless the user requests a different count, draft:

1. **Recommended** — the most complete and publishable point of view.
2. **Concise** — one short, natural reply.
3. **Expert** — a domain mechanism, trade-off, or second-order effect.
4. **Community** — a human, fan, builder, or user perspective without manufactured sentiment.
5. **Conversation starter** — a specific, answerable question rather than generic engagement bait.

Make the directions meaningfully different. Do not produce five paraphrases.

Read [references/angle-library.md](references/angle-library.md) when domain-specific framing is useful. Read [references/examples.md](references/examples.md) when calibrating format, uncertainty, or link disclosure.

## Write for the reply surface

- Keep each English option to 1–3 sentences unless the user asks otherwise.
- Lead with the insight; do not summarize the entire post.
- Prefer plain, natural English over report language.
- Add at most one core argument per option.
- Use a question only when it opens a real discussion.
- Match the source tone without copying its phrasing or escalating hostility.
- Avoid guarantees, exaggerated certainty, empty praise, and forced slang.

Useful structures include:

- `Main signal + why it matters + practical test`
- `Common reading + overlooked trade-off`
- `Conditional claim + implication + specific question`
- `Human reaction + contextual restraint`

## Handle links and affiliation

When the user supplies a related link:

1. Establish a useful connection to the source post first.
2. Add the link once, in the final sentence.
3. Describe what the reader will find at the link.
4. Disclose the operator's affiliation when it is relevant to how readers would interpret the recommendation.

Prefer wording such as:

```text
I work with the team behind this analysis, and we mapped the key signals here: [link]
```

Do not use `click now`, `go follow us`, fake neutrality, repeated links, or unsupported performance promises.

## Format the output

Use this structure:

```markdown
### Best pick

**English:** ...

**中文翻译：** ...

**Why this angle:** one short sentence

---

### Option 2 — Concise

**English:** ...

**中文翻译：** ...
```

Keep each Chinese translation accurate, natural, and no longer than needed for review. Include `Why this angle` for the best pick by default; omit angle explanations for the other options unless requested.

## Run a final integrity check

Before returning drafts, confirm that:

- Every option is faithful to the supplied source.
- The five angles are distinct.
- The English sounds like a reply, not a press release or AI summary.
- Uncertain facts remain conditional.
- Causation is not inferred from correlation.
- No option impersonates an independent user or fabricates community consensus.
- Any relevant affiliation is clear.
- The copy does not enable automated posting, spam, harassment, or coordinated amplification.
- A human can comfortably review and choose before publishing.
